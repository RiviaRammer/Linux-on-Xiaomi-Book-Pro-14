# Xiaomi Book Pro 14 TM2424 BIOS Update on Linux

This guide documents how to update the BIOS of the Xiaomi Book Pro 14 with
board ID `TM2424` on Linux using the official firmware payload.

The method uses the standard UEFI ESRT capsule-on-disk update path via `fwupd`.
It does not use `flashrom`, Intel FPT, AFU, or any direct SPI flash writing.

## 1. Updating With the Provided `TM2424.fd`

### Firmware Information

This firmware was extracted from Xiaomi's official Windows BIOS update package:

```text
Package: XMAPT4B0P0808.exe
Target device: Xiaomi Book Pro 14
DMI board: TM2424
Known board version: V14D1
Verified source BIOS: XMAPT4B0P0505
Target BIOS: XMAPT4B0P0808
BIOS release date: 2026-04-03
```

Firmware payload:

```text
File: TM2424.fd
Size: 23151568 bytes
SHA256: 5a4ba0edb7ffe02e434b6aff48e3c519989a4635111729d33ead62a9ff603aed
Target ESRT firmware version: 1899561011
Target ESRT firmware version, hex: 0x71390033
```

After a successful update, Linux should report:

```text
/sys/class/dmi/id/bios_version: XMAPT4B0P0808
/sys/class/dmi/id/bios_date:    04/03/2026
```

### Safety Notes

Make sure you are using a Xiaomi Book Pro 14 with board `TM2424`.

Check the board name:

```bash
cat /sys/class/dmi/id/board_name
cat /sys/class/dmi/id/board_version
cat /sys/class/dmi/id/bios_version
cat /sys/class/dmi/id/bios_date
```

Expected board name:

```text
TM2424
```

### Check the Firmware File

Before flashing, verify the file hash:

```bash
sha256sum TM2424.fd
```

Expected:

```text
5a4ba0edb7ffe02e434b6aff48e3c519989a4635111729d33ead62a9ff603aed  TM2424.fd
```

### Find the System Firmware Device

Install `fwupd` if needed:

```bash
sudo apt install fwupd
```

List firmware devices:

```bash
fwupdmgr get-devices --show-all
```

Find the entry named `System Firmware`.

It should look similar to this:

```text
System Firmware:
  Summary: UEFI System Resource Table device (Updated via capsule-on-disk)
  Vendor: XIAOMI
  GUID: 5fdb6955-bdaa-5f9c-8555-426f4c305f4f
```

You need either:

- the `Device ID` shown under your own `System Firmware` entry, or
- the ESRT GUID:

```text
5fdb6955-bdaa-5f9c-8555-426f4c305f4f
```

Do not copy another user's `Device ID` blindly. The `Device ID` is generated by
fwupd for the local device. The GUID above is the ESRT System Firmware GUID.

### Check the EFI System Partition

The EFI System Partition must be mounted:

```bash
findmnt /boot/efi
sudo fwupdtool esp-list
```

If `/boot/efi` is not mounted, mount your EFI System Partition first.

### Stage the BIOS Update

Use `fwupdtool install-blob` with the original `TM2424.fd` file.

Using the ESRT GUID:

```bash
sudo fwupdtool --prepare install-blob TM2424.fd \
  5fdb6955-bdaa-5f9c-8555-426f4c305f4f \
  1899561011
```

Alternatively, using your own `System Firmware` Device ID:

```bash
sudo fwupdtool --prepare install-blob TM2424.fd \
  YOUR_SYSTEM_FIRMWARE_DEVICE_ID \
  1899561011
```

When prompted:

```text
An update requires a reboot to complete. Restart now? [y|N]:
```

You may choose `N` first and inspect the staged capsule.

### Optional: Verify the Staged Capsule

Check the capsule file:

```bash
sudo fwupdtool esp-list
sudo ls -lh /boot/efi/EFI/UpdateCapsule/
```

You should see:

```text
/boot/efi/EFI/UpdateCapsule/CapsuleUpdateFile0000.bin
```

`fwupd` wraps `TM2424.fd` with a 4096-byte ESRT capsule header. The payload
after that header should match the original firmware:

```bash
sudo dd if=/boot/efi/EFI/UpdateCapsule/CapsuleUpdateFile0000.bin bs=4096 skip=1 status=none | sha256sum
sha256sum TM2424.fd
```

Both hashes should be:

```text
5a4ba0edb7ffe02e434b6aff48e3c519989a4635111729d33ead62a9ff603aed
```

### Reboot to Apply and Verify

Reboot:

```bash
sudo reboot
```

After Linux boots again:

```bash
cat /sys/class/dmi/id/bios_version
cat /sys/class/dmi/id/bios_date
fwupdmgr get-devices --show-all | sed -n '/System Firmware:/,/BootGuard/p'
```

Expected result:

```text
XMAPT4B0P0808
04/03/2026
Current version: 1899561011
```

## 2. Extracting Firmware From Future `.exe` Packages

Future Xiaomi BIOS update packages may use the same Insyde H2OFFT packaging
format. The goal is to extract the official, unmodified firmware payload.

Do not dump your own SPI flash and do not modify the firmware. The clean payload
should come from the official update package.

### Identify the Package Type

The known `XMAPT4B0P0808.exe` package is an Insyde H2OFFT / 7-Zip SFX based
Windows updater.

Useful indicators:

```text
H2OFFT-Wx64.exe
H2OFFT64.sys
InterToolx64.efi
package.bin
package.sig
*.fd
```

### Runtime Extraction Method

Run the official `.exe` on Windows. The updater extracts files to a temporary
directory, usually under:

```text
C:\Windows\Temp\7zSxxxx.tmp
```

or sometimes:

```text
%TEMP%
%LOCALAPPDATA%\Temp
```

Before closing any updater, error, or confirmation window, copy the temporary
directory to a safe location.

For the `XMAPT4B0P0808.exe` package, the extracted directory contained:

```text
TM2424.fd
H2OFFT-Wx64.exe
H2OFFT64.sys
H2OFFT.inf
H2OFFT.cat
InterToolx64.efi
BiosImageProcx64.dll
FlsHook.exe
package.bin
package.sig
Ding.wav
```

The firmware payload was:

```text
TM2424.fd
```

### Static Extraction Notes

Some Insyde packages contain an internal 7-Zip archive. In this package, an
unnamed extracted file with a GUID-like filename was itself a 7-Zip archive and
contained the same files listed above.

If a direct archive tool can open the payload, extract it and look for:

```text
*.fd
*.bin
*.rom
*.cap
package.bin
package.sig
H2OFFT-Wx64.exe
InterToolx64.efi
```

### Decode `package.bin`

In this package, `package.bin` was an encoded Insyde H2OFFT configuration file.
It could be decoded by shifting each byte right by one bit.

PowerShell example:

```powershell
$b = [IO.File]::ReadAllBytes("package.bin")
$decoded = [byte[]]::new($b.Length)
for ($i = 0; $i -lt $b.Length; $i++) {
    $decoded[$i] = ($b[$i] -shr 1)
}
[IO.File]::WriteAllBytes("package.decoded.txt", $decoded)
```

Important settings found in this package:

```ini
[FDFile]
FileName=

[Platform_Check]
Flag=1
PlatformName1=TM2424

[Region]
BIOS=1
GbE=0
ME=0
EC=0
DESC=0
Platform_Data=0

[SecureUpdate]
viaESP=3

[Others]
DisableSecureCapsuleFlash=0

[OEM]
RecoveryFilename=TM2424R1.fd
```

Interpretation:

- `FileName=` is empty, so H2OFFT loads the first FD file in the directory.
- `PlatformName1=TM2424` confirms the board target.
- `BIOS=1` means the update is for the BIOS region.
- `viaESP=3` indicates secure update through ESP or memory fallback.
- `DisableSecureCapsuleFlash=0` means secure capsule flashing is enabled.

### Verify Future Firmware

For a future package, record:

```text
Original package filename
Extracted firmware filename
File size
SHA256 hash
BIOS version string
BIOS release date
Target board name
```

Basic checks:

```bash
sha256sum NEW_FIRMWARE.fd
strings NEW_FIRMWARE.fd | grep -E 'XMAPT|TM2424|ESRT'
```

On Windows or Linux, inspect the header:

```bash
xxd -l 128 NEW_FIRMWARE.fd
```

The known `TM2424.fd` begins with an `MZ` PE header, because it is an Insyde
secure firmware payload, not a raw SPI image.

### Updating With a Future Firmware File

After confirming the future payload is the correct official firmware for
`TM2424`, use the same fwupd path:

```bash
sudo fwupdtool --prepare install-blob NEW_FIRMWARE.fd \
  5fdb6955-bdaa-5f9c-8555-426f4c305f4f \
  NEW_ESRT_VERSION_NUMBER
```

The ESRT version number must be updated for the new firmware. You can usually
find it from the extracted firmware metadata or from a successful Windows/Insyde
package analysis.

For `XMAPT4B0P0808`, the value was:

```text
1899561011
```

Do not use this version number for unrelated future firmware unless it is still
the exact same `XMAPT4B0P0808` payload.

### What Not To Do

Do not:

- flash this with `flashrom`;
- use Intel FPT to write the BIOS region;
- write raw SPI images;
- modify the firmware payload;
- use a firmware file for a different board;
- use another user's fwupd Device ID without checking your own System Firmware entry.

The correct path is:

```text
official Xiaomi package
-> extracted official Insyde .fd payload
-> fwupd install-blob
-> ESRT capsule-on-disk
-> BIOS verifies and applies the update
```
